# 双源 USDT 自动汇率

实现日期：2026-11-07。代码完成不代表已部署或已取得供应商商用授权。没有申请 Key、付费、真实转账或更改线上设置。

## 接口失败为什么仍可能建单

| 场景 | 官方 v2.0.0 的自动模式 | 上一批 QX 单源保护 | 本次可选双源模式 |
|---|---|---|---|
| 没有缓存且接口失败 | 无法得到汇率 | 拒绝新报价 | 拒绝新报价 |
| 已有缓存，接口暂时失败 | 可继续使用历史报价，无硬性最长年龄 | 仅在 48 小时硬期限内可用 | 仅沿用仍有效、曾通过双源核验的报价；默认从较旧来源的行情时间算最多 600 秒 |
| 接口返回新鲜但离谱的正数 | 可能采用 | 仍可能采用 | 两源偏差、人工范围、参考价或前价跳变任一超限，立即暂停新报价 |
| 之前检测到价格冲突，随后接口离线 | 没有冲突暂停机制 | 没有冲突暂停机制 | 保持暂停，不因离线重新启用旧价 |
| 已存在的具体付款订单 | 按创建时数量支付 | 保持原金额与地址 | 保持原金额与地址；新切链子单仍需通过核验 |

“接口故障”与“错误报价”不同：HTTP 429、5xx 或网络错误可以在短期内用可信缓存；缺字段、错误币种、异常价格、过期／未来／倒退时间戳等按不可信数据处理，暂停新报价。异常报价不会覆盖上一次可信报价。

## 启用方式

后台设置导航增加“Verified USDT rates / 双源汇率”，页面路径为 `/qx-rate-guard.html`；也可直接打开此路径。页面复用已有后台登录，提供中文／英文切换。上游仓库只有已编译前端，因此新增可维护的独立 HTML/CSS/JS，不重写压缩包内容。

1. 填写 CoinMarketCap 注册 Key 和 CoinGecko Key，选择对应的 CoinGecko Pro 或 Demo 端点。套餐选择不代表授予商用许可，需使用符合实际用途的授权。
2. 选择订单计价币 CNY 或 USD，填写每 1 USDT 对应的**人工核对参考价、最低价格、最高价格**。示例价格不是推荐的生产价格。
3. 设置允许偏差和最长有效时间，打开“在自动模式下启用”，保存。
4. 在原汇率设置将模式设为 `auto`，点击“重新核验”，确认有效报价与暂停原因。
5. 如需通知，在本页为已启用的现有通知渠道订阅“汇率异常”。只有订阅 `rate_alert` 的渠道收到消息，不自动订阅或修改其他事件。

新安装和升级默认不启用双源，固定模式仍是原有默认。双源启用且处于 auto 模式时，只支持 **USDT / 所选计价币**，所有 USDT 链共用报价；其他币对拒绝自动换算。包括 USD→USDT 也查询真实报价，不走原来的 1:1 特判。固定模式、未启用双源的单源模式保留原有逻辑。

Key 在数据库中的敏感配置内保存，通用设置列表不返回该配置；专用接口只回传是否已配置，不回显 Key。输入留空保留已存 Key。Key 不写入 URL、日志或订单快照，HTTP 重定向不携带 Key 跟随。数据库仍须按含敏感配置的数据库管理；本次没有新增数据库字段级加密。

## 采用的报价与边界

- 主源：CoinMarketCap 官方 `/v3/cryptocurrency/quotes/latest`，固定 USDT ID `825`，按所选币种请求 `CNY` 或 `USD`。校验资产 ID、符号、报价币种、状态和 `quote.last_updated`；适配 v3 的数组结构。
- 校验源：CoinGecko `/api/v3/simple/price`，固定 `ids=tether`，请求 `precision=full` 和 `include_last_updated_at=true`。
- 两个请求并发、总超时 6 秒。只访问固定官方 HTTPS 域名，不允许随意配置接收 Key 的网址。
- 两源都通过检查后采用 **CMC 主报价**；不取平均、不挑对商户更有利的价格，不静默退回日更源或固定价。
- 双源来自不同供应商，但可能共享部分底层市场数据，不能保证完全独立。API 行情和人民币实际兑付价也可能不同。

## 默认保护参数

| 参数 | 初始值 | 说明 |
|---|---:|---|
| 刷新间隔 | 300 秒 | 由请求触发；到刷新点同步核验，防止已发现异常后仍返回旧缓存。没有订单时不持续消耗额度 |
| 来源最长年龄 | 600 秒 | 按两源中更早的报价时间计算；重复抓到同一报价不会续期；允许配置至 1800 秒 |
| 两源最大时间差 | 180 秒 | 避免比较相隔过久的报价 |
| 两源偏差 | 1% | `abs(主价-校验价)/min(主价,校验价)`，超限暂停；支持调整 |
| 最大跳动 | 2% | 两源分别对比人工参考价及各自上次可信价，超限暂停；支持调整 |
| 人工价格范围／参考价 | 必填 | 不预填一个“永远合理”的经济价格；参考价不会随行情接口自动漂移 |
| 失败重试 | 60 秒 | 自动请求节流；管理员可手动强制核验 |
| 异常通知间隔 | 15 分钟 | 持续失败限频；状态和数据库保留具体原因 |

1% 和 2% 是保守的可调起始设置，不是行业标准或无损失保证。真实行情大幅变化也可能触发暂停，需管理员复核参考价和范围。价格恢复正常且通过全部检查后自动解除暂停；单纯时间流逝或服务重启不会解除价格异常暂停。

缓存和暂停状态保存到独立 `verified_rate_cache` 表，不与旧日更源缓存混用。变更配置／Key 会使旧配置对应的报价不可用；尚未完成的旧请求返回时也会丢弃。状态写入失败时当前进程停止提供报价，不使用未持久化的新价。

每笔新具体订单（含首次选链、切链子单、OkPay 路径）在同一建单写入中保存 `orders.rate_quote`，包含实际采用的换算率、来源、源时间、有效期等；状态变动不会改写旧订单快照。仍保持“优惠后实付金额 × USDT/计价币比例”，然后走原有精度与同址同额避让规则。

## 管理接口

均需已有后台 JWT：

- `GET /admin/api/v1/settings/rate/verified`：脱敏配置、最新观测、最近可信报价及可用状态。
- `PUT /admin/api/v1/settings/rate/verified`：原子保存整个双源配置；遗漏字段和留空 Key 保留当前值。
- `POST /admin/api/v1/settings/rate/verified/refresh`：强制核验，不跳过安全检查。
- 原有 rate status / refresh 在启用双源的 auto 模式下展示／刷新双源状态。

配置整体存为 `rate.verified_usdt`，通用设置更新／删除接口禁止修改它，防止上游表单意外覆盖。直接编辑数据库不属于受支持的操作方式。

## 验证与上线限制

已增加针对异常高低价、双源冲突、错误币种、格式变化、时间异常、短暂故障、过期、恢复、并发复用、持久化失败、重启保留暂停和凭据不回显的自动测试；建单集成测试覆盖优惠后金额、异常拒单、旧订单金额及地址锁不变。页面用本地模拟 API 检查中英文、保存和窄屏布局；模拟值不代表当前真实价格。

真实注册 Key 尚未提供，故未进行真实 Key 的额度／授权／端到端收款验收。现有线上默认模式未改变。部署前需备份配置和数据库；自动迁移增加 `verified_rate_cache` 表和 `orders.rate_quote` 字段，旧订单不会被补造历史汇率。
