- `CGO_ENABLED=0`、`-trimpath` 构建 Linux amd64 / arm64 均成功；构建标识为 `2.0.0-qx.1-dev`。没有上传发行包或替换线上镜像。
- GitHub Actions 对提交继续执行 Linux 全量测试、竞态检测、静态检查与双架构编译；合并前以对应提交的 `QX validation` 成功为准，结果保留在 Actions 和 PR 检查记录中。

最终检查中实际发现并修复了三个原有测试时序问题，没有跳过测试或关闭 race 检查：

1. Aptos 成功支付测试先生成交易、再创建订单，跨毫秒时被“付款不得早于订单”正确拒绝。调整为先建单再生成交易；重复运行使用不同 ledger version，避免被进程内真实防重缓存当作重复交易。连续 20 次通过，并补充了早于建单、缺失时间及同毫秒边界校验。
2. 回调重启测试看到数据库结果就重置队列，但旧 worker 的清理尚未结束。增加 worker 完成同步，模拟重启及销毁测试数据库前等待退出。
3. Telegram 通知路由测试结束时异步重载仍在访问共享环境。增加重载任务等待接口，清理测试环境前先等待完成；未改为同步阻塞管理员接口。相关回调和通知竞态测试连续 10 次通过。

测试使用临时 SQLite、模拟 RPC/HTTP 和模拟链上到账事件，不使用线上订单或真实钱包资金。没有进行真实主网转账，不声称“没有任何 bug”。当前只按单个网关实例的现有部署模型验证；多实例共享数据库、MySQL/PostgreSQL 的生产并发行为不在本轮验收内。

## 仍需单独处理的边界

1. 查单 API 与“同一订单号重复建单可再次打开收银台”是两件事。本批补上查单接口，未改变重复建单拒绝语义，匹配 QX 当前不提供旧订单继续支付的需求。
2. 金额锁修复不会解决所有迟到付款／主网节点异常问题，仍需真实 RPC 与回调闭环验收。
3. TON 积压／补单根哈希、运行目录前端资源可写等旧问题没有在此批统一解决。不能将首批维护版当作完整安全审计通过的发行版。
4. 自动汇率已在后续补丁加上有效期与源绑定；默认是每日参考价，无日期自定义接口无法验证其上游行情年龄。异常幅度检查、备用源和每订单来源快照仍未实现，详见汇率文档。
5. 发布流程尚不自动部署；旧 upstream 工作流已用 QX 的只读测试/编译 CI 代替，以免推送 tag 误调用原项目发布目标。原文件在官方 tag 中完整保留，修改前还在本地临时目录备份。

## 后续：自动汇率保护（2026-11-06）

继续审查 ralph-wren 的币安 C2C、中位数及缓存改动后，未整分支合入：其实现绑定交易所报价和订单路径，没有直接解决通用接口的旧报价期限、源切换与缺失币种续期问题。本轮由 QX 在现有通用接口上独立实现，不能表述为已合并币安功能。

- 增加公开默认源，保持后台／环境配置优先与 fixed 默认模式。
- 持久化报价日期与有效期，分开处理刷新 TTL 和 48 小时最长有效期；日期缺失仅兼容自定义源，内置每日源必须带有效日期。
- 更换源后同步取价并拒绝旧来源；按来源合并并发请求，串行核对并发布结果。
- 本次完整响应替换成功缓存，避免缺失币种获得新的有效期；失败只保留原有效期内的历史报价。
- 测试覆盖默认／自定义源、日期边界、旧缓存、数据库迁移、换源失败与在途换源、并发请求、部分响应、持久化故障、折扣换算及旧单付款金额保持。
- 新增默认源使原有“空地址就是接口不可用”的测试假设失效。该测试改为明确模拟默认源故障，保持“无有效报价不能创建订单”的原有断言，并防止测试意外访问真实网络。

本机 Go 1.26.1 / macOS arm64 验证已全部通过：`CGO_ENABLED=0 go test -count=1 ./...`、`go test -race -count=1 ./...`、`go vet ./...`，以及 Linux amd64／arm64 的 CGO0 编译。汇率模块另执行 `go test -race -count=10 ./config` 通过。GitHub Actions 继续对 PR 的确切提交执行 Linux 验证，通过后才合并；线上服务保持原版本。
