# 后台登录安全

本功能只保护 USDT-QX 管理后台，不改变商户签名、New API 回调或用户付款流程。代码提交不代表已部署，也不代表已替管理员绑定验证器。

## 使用

账号设置增加“登录安全”入口，地址 `/qx-security.html`，支持中文、英文与手机布局。

1. 输入当前密码，开始绑定；验证器扫描二维码，或手动输入密钥。
2. 输入验证器 6 位验证码，完成绑定。未确认或超过 10 分钟的绑定不会启用。
3. 保存显示的一次性恢复码。共 10 个，每个只能使用一次；服务端只存 SHA-256 摘要，无法再次显示原文。
4. 后续登录先验证密码，再弹出验证码输入框。也可输入恢复码；恢复码只替代验证码，不替代密码。

关闭两步验证、重新生成恢复码和改密码需要当前密码与第二因素。重新生成恢复码使旧集合立即失效。成功绑定、关闭或更换恢复码后，撤销全部旧会话，并为当前浏览器签发新会话（同浏览器页签共享登录 Cookie）；改密码或退出则撤销全部会话。登录验证码使用 30 秒周期，接受前后一个时间窗口；已经成功使用的时间窗口不可再次使用，请等待下一组验证码。

验证码和恢复码的消费通过数据库条件更新完成，并发请求也只能成功一次。密钥不通过用户资料、设置列表或状态接口回显；QR 在服务端生成，不提交给第三方二维码网站。管理 API 响应设置 `Cache-Control: no-store`。

## 加固及边界

- 登录、二步验证和安全变更在校验密码前预占尝试次数；同账号 15 分钟 12 次，同 IP 15 分钟 40 次。通过完整认证后重置账号计数，IP 计数保持至窗口结束。超过次数返回 HTTP 429 与 `Retry-After`。
- 当前计数是单进程内存状态，重启会清空；多副本部署需另配共享限流或入口限流。账号限流可能被恶意尝试触发短暂拒绝服务。
- 默认只取连接对端 IP，不信任客户端自行填写的转发头。反向代理场景可在服务端 `.env` 配置 `admin_trusted_proxies`，逗号分隔受信代理 CIDR；按实际部署填写，不要允许全部网段。使用 X-Forwarded-For 从右向左剥离受信代理；配置不正确时多个用户可能共享同一代理 IP 限额。
- 不存在的账号也执行 bcrypt 比较；已登录请求回查账号存在性、启用状态和会话版本。
- 初始密码指纹接口移到登录后；通用设置接口禁止写入／删除 JWT secret、初始凭据元信息和双源敏感配置，避免绕过专用入口。
- JWT 仅接受 HS256，并要求有效期、签发时间、账号与会话版本。升级前签发且不含版本的旧 JWT 将失效，管理员需重新登录。
- JWT 解析限制令牌长度，并将直接使用的 `golang-jwt/jwt/v4` 升级至修复 CVE-2025-30204 的 `v4.5.2`。此项不等于已完成全部依赖的安全审计。
- TOTP 不防钓鱼代理。此实现没有宣称具备 Passkey／WebAuthn，也没有完整设备列表或逐设备撤销。

## 加密密钥和升级

验证器密钥使用 AES-256-GCM 加密，附加数据绑定管理员 ID。加密密钥存于 `${runtime_root_path}/admin-mfa.key`，首次绑定时生成，权限 `0600`；可通过 `admin_mfa_key_file` 指定独立持久化文件。数据库与文件应分开保护，禁止将文件放到公开静态目录。

部署前备份数据库、配置和已有密钥文件，持久化运行目录。自动迁移在 `admin_users` 增加会话版本及 MFA 字段。仅恢复数据库而没有对应密钥文件，会使验证器校验不可用；代码不会在解密时静默生成新密钥。持有密码和恢复码时，仍可以登录、关闭旧绑定并重新绑定。密码与验证器及恢复码同时丢失时，本版本不提供公开的 MFA 绕过接口，应走服务器维护恢复流程。

上游仅提供压缩后的前端。新增安全设置页与 `qx-auth-bridge.js`，后者仅为原登录／改密请求处理二步验证挑战，不修改压缩 bundle；后端独立强制验证，禁用脚本不会绕过 MFA。升级上游前端时需回归登录、改密与账号导航。

## 验证

自动测试覆盖密码单因素不能签发 MFA 会话、错误／过期绑定、重复 TOTP、恢复码复用、并发消费、密钥丢失、账号替换、旧会话撤销、限流、代理头伪造及敏感设置覆盖。浏览器用模拟 API 验证中英文页面、手机布局、绑定／恢复码隐藏和登录弹窗；模拟页面验收不等于真实设备扫码或线上支付验收。
