# 自动与固定汇率说明

核对日期：2026-11-06。范围：官方 v2.0.0 的源码与 QX 首批补丁。没有启用线上自动汇率，没有接入币安账户或币安 C2C。

## 给使用者的简短说明

自动汇率是由网关从指定的报价接口自动获取换算比例，不需要登录交易所。固定汇率由管理员填写。选择币安只是选择某一种报价来源，并不是自动汇率的前提。

New API 先计算优惠后的应付金额，再把该金额交给 USDT 网关换算。例如充值 100、优惠 10%，传入网关的是 90；假设 1 USDT = 8 元，换算为 11.25 USDT。实际支付以收银台最终显示数量为准，因为金额精度和同址同额订单避让可能调整尾数。

## 已核实的现有行为

| 项目 | 实际实现 |
|---|---|
| 模式 | 已有 `fixed` / `auto`；新安装默认为 `fixed` |
| 固定报价 | `rate.forced_rate_list` 内保存每 1 单位原币可换得多少目标币；例 CNY→USDT 的值 0.125 表示 1 USDT = 8 CNY |
| 自动报价 | `rate.api_url` 后附加 `/<base>.json`；例如 CNY 请求 `/cny.json`，解析 `cny.usdt` |
| 优先级 | auto 使用接口／缓存，不自动套用 fixed 的报价；fixed 不请求外部报价接口 |
| 缓存 | 默认 TTL 为 300 秒，可设置 10—86400 秒；这不是每 5 分钟运行的后台定时抓取任务 |
| 刷新触发 | 初次需要报价时同步获取；有旧缓存且达到 TTL 时，当前请求先返回缓存并异步刷新；后台也可手动刷新 |
| 接口失败 | 有历史报价则继续使用历史报价；没有可用报价则拒绝建单，不按 0 报价下单 |
| 旧订单 | 创建时保存 `amount` 和 `actual_amount`；之后查看同一收银台不会重新换算。QX 新增回归测试覆盖刷新报价和清空内存缓存后仍保留付款金额 |
| 切换链 | 新建链上的子单时会重新取价。当前并非整个父子订单共享永久汇率快照，不应把它说成“切任意链金额都不变” |
| USD→USDT | 当前 auto 对 USD→USDT 按 1:1 特判；不是通过市场接口追踪 USDT 脱锚。fixed 可设置该币对固定值 |

## 报价源与“实时”的区别

官方发行镜像的 `.env` 中包含 `fawazahmed0/currency-api` CDN 地址；仓库 `.env.example` 本身留空。部署环境的配置和数据库设置可以覆盖镜像默认值。因此，镜像里有地址，不代表某个线上实例已经启用它。

该数据源自己的 README 标明 **Daily Updated（每日更新）**。网关每 300 秒检查缓存，不会把每日数据变成秒级行情。若采用这个源，应称为“自动获取参考汇率”，不称为实时交易所成交价。

接口兼容样例：

```json
{"date":"2026-11-06","cny":{"usdt":0.125}}
```

示例数值仅用于解释，不是当日报价。

## 本轮保留的边界与后续选择

- 未合并 ralph-wren/HRET 的币安报价和币安充值流水监听：用户需要自动汇率，但未要求绑定币安。
- 先保留官方通用接口架构，最终选定报价源后再决定刷新频率和可接受的偏差。
- 官方旧报价回退目前没有硬性的最长使用期限，并且只按整份缓存记录成功时间；部分币种缺失时可保留更老报价。这是启用自动模式前需完善的规则，不能用“有回退”来声称长期断网也安全。
- 缓存按 base 组织。更换报价源后可能短暂保留原来源的缓存；启用或更换来源时需显式刷新并检查返回来源、更新时间和报价，再对外收款。
- 当前没有增加汇率异常幅度保护、每订单来源快照或“报价过旧停止新建单”的管理界面。下一步应根据选择的数据源独立实施，避免为了币安特性改动整个支付流程。
- 收款验收需分别验证折扣金额、尾数避让、切链、缓存失败、回调校验；本轮未发送真实链上资金。
