# 自动与固定汇率说明

2026-11-07 新增可选 [双源 USDT 自动汇率](verified-rates.md)，包含报价异常暂停和分钟级有效期。下文描述保留的固定／单源模式；双源开关默认关闭，启用后以新文档为准。

核对日期：2026-11-06。范围：官方 v2.0.0、QX 首批维护补丁及后续自动汇率保护。仓库更新不代表线上已升级或已启用自动模式。

## 使用方式

- **固定汇率**：选择 `fixed`，管理员填写换算比例；不请求报价接口。新安装默认仍为固定模式。
- **自动汇率**：选择 `auto`，网关自动获取报价。后台 API 地址优先，其次现有 `.env`／环境变量；都未设置时使用内置默认来源，不需要自己找接口，也不需要交易所账号或 API Key。
- 想使用其他来源，可在现有 API 地址框填写兼容地址。后台地址留空不会覆盖已有的环境变量地址；要明确使用内置来源，可把下方完整地址填入后台。

内置默认地址：

```text
https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@latest/v1/currencies
```

该项目自己的 README 标明 **Daily Updated（每日更新）**。这是自动获取参考汇率，不是秒级交易所行情。缓存默认每 300 秒具备刷新条件，并不意味着上游每 300 秒产生新报价。该源用于 USDT/CNY 参考换算；本轮未验证每日报价对高波动币种的适用性。

现有后台继续使用模式选择、API 地址、缓存 TTL、固定报价和手动刷新；没有新增供应商下拉菜单。新增的报价日期、失效时间及可用标记通过状态 API 提供，未重建上游编译后的前端界面。

## 金额怎么算

New API 先计算优惠后的应付金额，再交给网关换算。例如充值 100、优惠 10%，传入网关的是 90；假设 1 USDT = 8 元，换算为 11.25 USDT。实际支付以收银台最终显示数量为准，金额精度和同址同额订单避让可能调整尾数。

API 基地址会自动附加 `/<base>.json`，例如 CNY 请求 `/cny.json`。兼容响应：

```json
{"date":"2026-11-06","cny":{"usdt":0.125}}
```

`0.125` 表示 **每 1 CNY 可换 0.125 USDT**，即 1 USDT = 8 CNY；不是填 8。示例不是当日报价。固定报价 JSON 也使用这个方向。

## 这次与官方实现的区别

| 场景 | 官方 v2.0.0／QX 首批 | 本轮 QX 改动 |
|---|---|---|
| API 地址都为空 | 没有代码默认源；镜像可能另带环境配置 | 使用上述内置默认源，仍保留显式配置优先级 |
| 抓取时间和报价日期 | 只记录成功抓取时间 | 分开保存报价日期、抓取时间、失效时间 |
| 一直抓到同一天的报价 | 每次成功刷新都更新缓存时间 | 不延长该日期对应的失效时间 |
| 接口长时间故障 | 有历史报价即可继续使用，无硬性最长年龄 | 仅有效期内允许旧报价；过期后无有效新报价则拒绝新建单 |
| 更换来源 | 可能继续使用原来源缓存 | 立即按新来源获取；失败也不使用旧来源金额 |
| 换源时旧请求才返回 | 缓存没有按来源隔离 | 合并同源并发请求；发布前核对来源，丢弃旧来源响应 |
| 返回部分币种 | 缺失币种被合并，随整份缓存获得新时间戳 | 成功时整体替换，只给本次实际返回的币种有效期 |
| 升级前的缓存 | 没有失效元数据 | 首次自动换算重新获取，不凭空给旧数据续期 |

## 刷新与有效期

- TTL 默认 300 秒，可配置 10—86400 秒。刷新由请求触发，后台可手动刷新；不是后台定时轮询。
- 冷缓存同步抓取。有缓存、过了 TTL 但报价仍有效时，当前请求可用缓存并异步刷新。
- **有效期上限是独立于 TTL 的 48 小时，当前为代码固定值。**
- 响应含 `date` 时，以该日期的 **UTC 零点 + 48 小时** 为失效时刻。例如 `2026-11-05` 的报价在 `2026-11-07 00:00 UTC`（北京时间 11 月 7 日 08:00）失效。不是从每次抓取重新延长 48 小时。
- 内置源必须返回有效日期。任何来源只要提供日期，都要通过格式、非未来、未过期校验。
- 为兼容已有自定义接口，完全不含 `date` 时按成功抓取时间 + 48 小时限定缓存寿命。**这无法证明自定义源的底层行情有多新**；反复返回无日期的陈旧数据无法靠客户端识别。
- 到达硬期限后同步尝试刷新；失败返回不可用，建单层拒绝新单。失败重试受 TTL 节流，管理员可强制刷新；不会偷偷改用固定汇率。
- 自动刷新若缺少当前需要的币种，整次刷新视为失败，保留旧缓存原本的失效时间。手动刷新接受有效的部分币种响应，但移除缺失币种；下一次获取该币种时可能暂时无法建单。

新增 `rate_cache.quote_date`、`rate_cache.expires_at` 两个数据库字段，通过现有 AutoMigrate 升级；已覆盖旧 SQLite 表迁移、持久化更新和清空内存后恢复。状态 API 的 `is_usable` 表示该基础货币缓存来自当前源且在有效期内，不代表包含所有目标币种；`last_refresh_ok` 仅表示上次刷新结果。

## 原有支付规则保留

- 已创建订单保存 `amount` 和 `actual_amount`，查看同一收银台不重新换算。即使报价过期且接口故障，原订单的付款目标与金额锁仍保留。
- 切换链时创建新的子单会重新取价，因此报价不可用时也可能无法切换链；并非整个父子订单共享永久汇率。
- auto 对 USD→USDT 仍按 1:1 特判，不通过行情接口追踪脱锚；fixed 可设置该币对固定值。
- 未加入币安 C2C、币安账户流水监听、自动备用来源、异常幅度阈值或每笔订单的报价来源快照。
- 未真实转账、未部署新版、未改变线上模式。启用前仍需按实际收款链与回调做验收。
